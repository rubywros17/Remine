# Remine 서비스 기획서 (spec)

> 서비스명: **Remine** (리마인)
> 작성일: 2026-10-07 · 상태: MVP 기획 단계

### 이름의 의미
- **re** (다시) + **mine** (캐내다 / 내 것)
- "묵혀둔 캡처를 다시 캐내서, 다시 내 것으로" — 발음이 *remind*와 거의 같아 리마인드 서비스라는 점도 함께 전달된다.
- 참고: 동명의 해외 서비스(부동산 플랫폼, 메모 앱)와 유사 이름 앱(Remini)이 있어, 정식 출시 시 스토어 부제·상표 확인 필요.

### 브랜드 컬러
> 회색 돌 더미(쌓인 캡처) 속에서 맑게 떠오르는 기억(셀라돈)을 반짝 캐내는 순간(레몬)

| 역할 | 이름 | HEX | 쓰는 곳 |
|---|---|---|---|
| 기본 | Cool Gray | `#6F6F71` | 글씨, 아이콘, 테두리 |
| 메인 브랜드 | Celadon | `#7DC4CE` | 로고, 탭바 선택, 카테고리 카드 |
| 메인 진한 버전 | Deep Celadon | `#3E8F9A` | 흰 글씨가 올라가는 버튼 |
| 포인트 | Lemon Yellow | `#EDE7B3` | **잊은 관심사 알림 카드 전용**, 새로 감지된 태그 |
| 배경 | Off White | `#F5F5F4` | 앱 전체 배경 |

- 셀라돈·레몬은 밝아서 흰 배경 위 **글씨 색으로 쓰지 않는다.** 면·배경으로만 쓰고 위 글씨는 회색 계열.
- 레몬은 관심사 알림에만 써서 "Remine이 꺼내준 것"이라는 인식을 색으로 만든다.

## 1. 한 줄 소개

캡처해두고 잊어버린 스크린샷을 자동으로 분류해 예쁘게 보여주고, 자주 캡처했던 **잊은 관심사**를 먼저 꺼내서 알려주는 앱.

## 2. 문제 정의

- 사람들은 나중에 보려고 스크린샷을 저장하지만, 앨범에 쌓이기만 하고 다시 보지 않는다.
- 그 안에는 사고 싶었던 상품, 보고 싶었던 영화·드라마, 가보고 싶은 장소 같은 **본인의 관심사**가 담겨 있다.
- 기존 스크린샷 정리 앱은 대부분 "검색하면 찾아주는" 수동적인 도구에 머문다.

## 3. 차별점

| 기존 앱 | 이 서비스 |
|---|---|
| 내가 검색해야 찾아줌 | 서비스가 **먼저 말 걸어줌** |
| 분류·검색 중심 | 분류 + **관심사 패턴 감지 + 리마인드** |
| iOS·Pixel 위주 | **갤럭시(안드로이드) 우선** — Pixel Screenshots는 Pixel 전용 |

## 4. 타깃

- 1차: 스크린샷을 많이 찍는 한국 갤럭시 사용자 (개발자 본인 포함)
- 2차: iOS 사용자 (MVP 이후 확장)

## 5. MVP 범위

### 목표
> 갤럭시 앨범의 스크린샷을 자동으로 카테고리별로 예쁘게 보여주고, 자주 캡처한 관심사를 주 1회 알려준다.

### ✅ MVP 기능

**F-01. 스크린샷 불러오기**
- 앨범의 `Screenshots` 폴더만 읽는다.
- 첫 실행 시 최근 N장(기본 300장)만 분석해 첫 경험을 빠르게 한다.
- 이후 새로 추가된 스크린샷만 증분 분석한다.

**F-02. 자동 분류 + 태그**
- 기기 안에서 OCR로 텍스트 추출 (ML Kit, 한국어).
- **분류 입력은 하이브리드**다. 기기에서 OCR 글자 수(공백 제외)를 세어 기준값과 비교한다.
  - **기준값 이상(기본 150자)**: OCR **텍스트만** 서버로 전송한다.
  - **기준값 미만**: 텍스트와 함께 **긴 변 1024px로 축소한 이미지**를 보낸다. 단, 사용자가 **이미지 분석에 동의한 경우에만**이다.
    동의하지 않았으면 텍스트만 보내며, 이 경우 짧은 캡처의 정확도가 낮아진다(실험: 50자 미만 텍스트만 13.3%, 이미지 포함 80.0%).
  - 기준값은 하드코딩하지 않고 **설정**으로 둔다(서버 설정 `analysis.image-threshold-chars`, 기본 150, 앱이 받아서 사용).
  - 기기 안에서 먼저 **민감 정보 필터**를 거친다([개인정보 원칙](#개인정보-원칙) 참고).
    - **강한 민감 정보**(주민등록번호, 카드·계좌번호, 인증번호(OTP), 비밀번호): 서버로 보내지 않고 기기에서 `ETC`로 분류한다. 텍스트·이미지 모두 기기를 떠나지 않는다.
    - **전화번호**: 차단하지 않는다. OCR 텍스트에서 `[전화번호]`로 가린 뒤 **텍스트만** 보내고 이미지는 보내지 않는다.
    - **은행·증권·메신저 앱 캡처**: 서버로 보내지 않고 기기에서 앱 기준으로 바로 분류한다(메신저 → `CHAT`, 은행·증권 → `ETC`).
- LLM(`gemini-3.5-flash-lite`, temperature 1.0)이 카테고리·태그·한 줄 요약을 생성한다. 근거와 한계는 `experiment/SUMMARY.md`.
- 기본 카테고리 (고정). 코드 값(enum) → 앱 표시 라벨:

  | 코드 값 | 앱 표시 라벨 | 비고 |
  |---|---|---|
  | `SHOPPING` | 쇼핑 | 상품, 가격, 구매, 장바구니, 배송. 가격·할인·장바구니·배송이 보이면 대개 SHOPPING |
  | `ENTERTAINMENT` | 문화생활 | 영화·드라마·OTT·연극·뮤지컬·공연·전시·책·음악 등 보고 싶은 작품·콘텐츠 |
  | `PLACE` | 맛집/장소 | 맛집·카페·팝업스토어·여행지 등 "가보고 싶은 곳" (운영 기간이 있어도 장소가 핵심이면 PLACE). 주소·영업시간·메뉴·위치가 보이면 대개 PLACE |
  | `INFO` | 정보/꿀팁 | 뉴스·꿀팁·방법 설명, 레시피·DIY·코디처럼 "알아두거나 따라 해보려는 것" |
  | `CHAT` | 대화 | 메신저·댓글 대화. 메신저 앱 캡처는 기기에서 바로 `CHAT`으로 분류한다(서버로 보내지 않음, 일반 캡처처럼 노출) |
  | `SCHEDULE` | 일정/예약 | 작품 자체가 아니라 날짜·예약·티켓 오픈이 핵심이면 SCHEDULE. 특정 날짜·시간, 예매 오픈, 예약 완료가 핵심이면 SCHEDULE |
  | `ETC` | 기타 | |

**F-03. 정리 화면**
- 홈: 카테고리 카드 + 썸네일 미리보기
- 카테고리 상세: 이미지 그리드 + 태그 칩 필터
- 스크린샷 상세: 원본 이미지 + AI 요약 + 태그
- **"분석 제외" 필터**: 서버 분석을 거치지 않고 기기에서 분류된 캡처(강한 민감 정보, 은행·증권 앱)를 모아 본다.
  이 캡처들은 정리 화면에서 **기본 숨김**이다. 메신저 앱 캡처(`CHAT`)는 일반 캡처처럼 노출한다.
- 홈의 카테고리별 개수·썸네일은 서버 집계와 기기 내 분류 결과를 합쳐 보여준다.

**F-04. 잊은 관심사 알림**
- 서버가 태그 빈도를 집계해 관심사를 감지한다.
  - 규칙 예시: 최근 14일 안에 같은 태그 3회 이상
- 주 1회 푸시 알림 (FCM)
  - 예: "요즘 '니트 가디건'을 4번 캡처했어요 👀"
  - 예: "한 달 전에 저장한 드라마, 아직 안 봤죠?"

**F-05. 사용자 카테고리 수정**
- AI가 분류한 카테고리가 틀리면 사용자가 스크린샷 상세 화면에서 **7개 기본 카테고리 중 하나로 직접 바꾼다.**
- 수정한 값은 AI 분류보다 우선하며 이후 재분석이 덮어쓰지 않는다. 서버에는 `category_source`(AI / USER)로 구분해 저장한다.
- 홈의 카테고리별 개수·대표 태그·썸네일은 수정된 카테고리를 기준으로 집계한다.
- 정정 데이터는 이후 분류 품질 평가용 라벨로 쓸 수 있다(분류 정확도 검증 데이터 확보).
- 새 카테고리를 만드는 **사용자 정의 카테고리**와는 별개이며 MVP 이후다.

### ⏳ MVP 이후

| 기능 | 미룬 이유 |
|---|---|
| 다운로드 폴더 사진 정리 | 스크린샷보다 분류가 애매함 |
| 인스타 게시물 공유하기로 넣기 | Share Intent 별도 구현 필요. 인스타는 저장 목록 공식 API가 없어 자동 연동 불가 |
| 글자 없는 이미지 분석 (옷 사진 등) | 하이브리드 분류가 OCR이 짧은 캡처에 이미지를 쓰긴 하지만, 사진 위주 이미지 전반의 품질·비용은 검증 전 |
| 할인·OTT 공개 알림 | 외부 데이터 연동 필요, 수익화 단계에서 |
| 사용자 정의 카테고리 (새 카테고리 추가) | 기본 분류 품질 확보 후. 7개 중 다시 지정하는 수정은 F-05로 MVP에 포함 |
| 로그인 / 계정 | MVP는 기기 ID로 충분 |
| iOS 출시 | 안드로이드 MVP 검증 후 |

## 6. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 앱 | **Flutter** (Dart) | 안드로이드 우선, iOS는 이후 맥북에서 빌드 |
| 기기 OCR | `google_mlkit_text_recognition` | 한국어 스크립트 사용 |
| 앨범 접근 | `photo_manager` | |
| 푸시 | Firebase Cloud Messaging (`firebase_messaging`) | |
| 서버 | **Spring Boot** (Java) | 백엔드 포트폴리오 핵심 |
| DB | 미정 (PostgreSQL 또는 MySQL) | |
| LLM | **`gemini-3.5-flash-lite` 확정**, temperature **1.0** | 실험(43장)에서 텍스트만 41.9% / 텍스트+이미지 74.4% / 하이브리드 79.1%. 선택 이유(무료 한도·비용)와 한계는 `experiment/SUMMARY.md`. 운영은 **유료 등급** |
| 분류 입력 | **하이브리드** (OCR 기준값 이상 텍스트만 / 미만 텍스트 + 축소 이미지) | 기준값은 설정(기본 150자), 이미지는 동의한 경우에만 |

## 7. 아키텍처

```
[Flutter 앱]
  ├─ 앨범에서 스크린샷 읽기 (photo_manager)
  ├─ 기기 내 OCR (ML Kit)
  ├─ 기기 내 민감 정보 필터 · 앱 기반 분류
  │    강한 민감 정보(→ ETC), 은행·증권(→ ETC), 메신저(→ CHAT) 캡처는 기기에서 직접 분류,
  │    텍스트·이미지 모두 기기를 떠나지 않음 / 전화번호는 [전화번호]로 가린 뒤 텍스트만 전송
  ├─ OCR 글자 수 ≥ 기준값 → 텍스트 + 메타데이터만 전송
  │  OCR 글자 수 < 기준값 → (이미지 분석 동의 시) 긴 변 1024px 축소 이미지를 함께 전송
  ├─ 원본 이미지는 기기에만 보관     ← 서버로 가는 것은 분석용 축소본뿐
  └─ 정리 UI / 카테고리 수정 / FCM 푸시 수신

[Spring Boot 서버]
  ├─ 분석 API: 텍스트(+ 축소 이미지) → LLM → 카테고리·태그·요약 저장
  │            이미지는 메모리에서 LLM으로 전달만 하고 저장·로그하지 않음
  ├─ 관심사 집계 스케줄러 (주 1회)
  └─ FCM 푸시 발송

[DB]
  └─ device / screenshot / tag / screenshot_tag / interest_alert
```

### 개인정보 원칙
> **민감한 캡처는 기기를 떠나지 않고, 분석용 이미지는 동의한 경우에만 보내며 서버에 저장하지 않는다.**

- 서버가 저장하는 것은 OCR 텍스트, 카테고리, 태그, 요약, 메타데이터뿐이다. **이미지는 저장하지 않는다.**
- 원본 이미지는 기기에만 있고, 서버로 가는 이미지는 분석용으로 줄인 축소본(긴 변 1024px)이다.

### 안전장치
| 장치 | 내용 |
|---|---|
| 기기 내 민감 정보 필터 (2단계) | ① **강한 민감 정보**(주민등록번호, 카드·계좌번호, 인증번호(OTP), 비밀번호) 패턴이 OCR 텍스트에 보이면 **서버로 보내지 않고 기기에서 `ETC`로 분류**한다. 텍스트·이미지 모두 기기를 떠나지 않으며, 정리 화면에서 기본 숨김이고 "분석 제외" 필터에서 모아 본다. ② **전화번호**는 차단하지 않고 OCR 텍스트에서 `[전화번호]`로 **가린 뒤 텍스트만** 보낸다(이미지는 번호가 그대로 있으므로 보내지 않음). 가게 전화번호가 많은 `PLACE` 캡처가 통째로 빠지지 않게 하기 위함이다. 패턴 목록과 마스킹 규칙은 구현 단계에서 정한다. |
| 앱 기반 기기 내 분류 | **은행·증권·메신저 앱에서 찍은 캡처**는 "분석에서 제외"하지 않고 **서버로 보내지 않은 채 기기에서 바로 분류**한다. 메신저 앱 → `CHAT`(일반 캡처처럼 노출), 은행·증권 앱 → `ETC`(기본 숨김, "분석 제외" 필터에서 조회). 그래서 `CHAT` 카테고리는 유지되고 **대화 내용은 기기 밖으로 나가지 않는다**. 앱은 **갤럭시 스크린샷 파일명의 앱 이름**으로 판별한다(예: `Screenshot_날짜_시간_앱이름.jpg`). 앱 이름 목록은 구현 단계에서 정한다. |
| 이미지 분석 동의 (끄기 가능) | 첫 실행 때 이미지가 분석을 위해 전송됨을 알리고 동의를 받는다. 설정에서 언제든 끌 수 있고, 끄면 이미지 없이 텍스트만 보낸다. |
| 이미지 저장·로그 없음 | 서버는 수신한 이미지를 디스크·DB·객체 저장소에 쓰지 않는다. 요청·오류 로그에도 이미지(base64 포함)를 남기지 않는다. |
| 운영은 유료 등급 | LLM 제공사의 무료 티어는 입력이 제품 개선에 쓰일 수 있다. 운영 환경은 유료 등급(입력이 학습에 쓰이지 않는 조건)만 사용한다. 개발·실험 중 무료 티어로 개인 캡처를 보낼 때는 이를 알고 쓴다. |
| 처리방침 고지 | 이미지 전송 여부, 제3자(LLM 제공사) 처리, 저장하지 않는 항목, 동의 철회 방법을 개인정보 처리방침에 명시한다. |

## 9. API (초안)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/devices` | 기기 등록 (FCM 토큰 포함) |
| GET | `/api/config` | 분석 설정 조회. 이미지 동봉 기준값(`analysis.image-threshold-chars`, 기본 150) 등 |
| POST | `/api/screenshots/analyze` | OCR 텍스트 배치 전송 → 분류 결과 반환. OCR이 기준값 미만이고 동의한 항목만 축소 이미지를 함께 보낸다(이미지는 저장·로그하지 않음) |
| PATCH | `/api/screenshots/{id}/category` | 사용자가 카테고리 수정 (7개 중 하나). `category_source`가 USER로 바뀌고 이후 재분석이 덮어쓰지 않음 |
| GET | `/api/screenshots?category=&tag=&page=&size=` | 분류된 스크린샷 목록. taken_at 최신순, page 기본 0 / size 기본 30·최대 100, 각 항목에 태그 포함 |
| GET | `/api/categories/summary` | 홈 화면용. 7개 카테고리 전부 반환(0장은 count 0), 카테고리별 개수·대표 태그 상위 3개·최신 localAssetId 4개 |
| GET | `/api/interests` | 감지된 관심사 목록 |

- 기기 등록(`POST /api/devices`)을 제외한 모든 API는 `X-Device-Id` 헤더로 기기를 식별한다. 미등록 기기는 404, 헤더 누락은 400. (로그인 없는 MVP의 임시 방식)

## 11. 리스크

- **분류 정확도**: 스크린샷은 텍스트가 섞여 있어 LLM이 헷갈리기 쉽다 → 1~2주차에 실제 스크린샷 50장으로 프롬프트 검증.
- **LLM 비용**: 첫 실행 시 대량 분석 → 배치 처리 + 최근 N장 제한. 이미지를 쓰면 장당 비용이 약 2.4배(실험 기준 $0.24 → $0.58 / 1,000장)이므로 짧은 캡처에만 쓰는 하이브리드로 완화.
- **글자 없는 스크린샷**: OCR 텍스트가 없는 캡처는 이미지 분석에 동의한 경우 이미지로 분류하고, 동의하지 않았으면 `기타`로 분류 (MVP 한계로 명시).
- **개인정보**: 분석용 이미지가 제3자(LLM 제공사)로 전송된다. 민감 정보 필터, 동의(끄기 가능), 저장·로그 없음, 유료 등급, 처리방침 고지로 완화한다.
- **앱 이름 판별의 한계**: 앱 기반 분류는 갤럭시 스크린샷 파일명(`Screenshot_날짜_시간_앱이름`)의 앱 이름에 의존한다.
  다른 제조사는 파일명 규칙이 다르고, 언어 설정에 따라 앱 이름이 달라지며(한글/영문), 앱 이름이 바뀔 수도 있어 판별이 빗나갈 수 있다.
  빗나가면 은행·메신저 앱 캡처가 일반 경로로 전송될 수 있으므로 OCR 패턴 필터(강한 민감 정보)를 이중 방어로 둔다. 갤럭시 외 기기는 MVP에서 판별을 보장하지 않는다.
- **기기 내 분류 캡처는 서버 집계·관심사 알림에 반영되지 않는다 (의도된 동작)**: 개인정보 보호를 위해 이 캡처들은 서버로 가지 않으므로
  `/api/categories/summary`와 관심사 알림(F-04)에 포함되지 않고, 앱이 기기에서 보관·합산한다. 사용자 카테고리 수정(F-05)도 이 캡처는 기기에만 저장된다.
- **전화번호가 있는 캡처는 텍스트만으로 분류된다**: 이미지를 보내지 않으므로 OCR이 짧아도 하이브리드의 이미지 경로를 쓰지 못해 정확도가 낮을 수 있다.
- **하이브리드 기준값의 일반화**: 150자는 43장·Tesseract OCR로 고른 값이다. ML Kit OCR과 더 큰 표본으로 재검증하기 전까지 설정값으로 두고 고정하지 않는다.
- **무료 한도**: 일반 `gemini-3.8-flash`는 무료 한도가 작아(하루 20회) 개발·검증에는 `gemini-3.5-flash-lite`를 쓴다.
