# LLM 분류 실험 요약

> 2주차 `LlmClassifier`를 정하기 위한 실험의 결론. 수치의 원본은 `results.*.md`(집계 수치만)이고,
> 파일명·OCR 텍스트·오답 상세는 개인 데이터라 커밋하지 않는다.

## 결론

| 항목 | 결정 |
|---|---|
| 모델 | **`gemini-3.5-flash-lite`**, temperature **1.0** |
| 분류 입력 | **하이브리드** — OCR 150자 이상이면 텍스트만, 150자 미만이면 텍스트 + 축소 이미지 (기준값은 설정). 정확도 **76.7~79.1%** (두 번 측정) |
| 프롬프트 | **v1 유지.** v2(경계 규칙 추가)는 채택하지 않음 — SHOPPING 회귀 ([프롬프트 v2 실험](#프롬프트-v2-실험-2026-10-16)) |
| 이미지 전송 | 사용자가 동의한 경우에만, 긴 변 1024px로 축소해 전송, 서버에 저장하지 않음 |

## 조건

- 표본 43장(본인 갤럭시 스크린샷, 1인 라벨링). 실행일: 1차 2026-10-15, v1 재실행·v2 2026-10-16
- OCR은 앱의 ML Kit이 아니라 **Tesseract(kor+eng)** — 근사치
- 모든 후보가 같은 프롬프트(카테고리 7개 고정, JSON 응답), temperature 1.0(Gemini 3 공식 권장값)
- 이미지 변형: 원본을 긴 변 1024px JPEG로 줄여 OCR 텍스트와 함께 전송

## 1. 텍스트만 vs 텍스트 + 이미지 (프롬프트 v1)

| 입력 | 정확도 (1차 → 재측정) | 평균 응답 | 장당 비용 | 1,000장 비용 | 평균 입력 토큰 |
|---|---|---|---|---|---|
| 텍스트만 | **41.9%** (18/43) → 44.2% (19/43) | 4.8초 | $0.000239 | $0.24 | 456 |
| 텍스트 + 이미지 | **74.4%** (32/43) → 74.4% (32/43) | 6.1초 | $0.000580 | $0.58 | 1,554 |

- 이미지를 더하면 정확도가 약 30%p 올랐고 비용은 약 2.4배, 응답은 약 1.4초 느려졌다. 응답·비용·토큰은 1차 측정 값이다.
- 호출 실패·파싱 실패는 두 후보 모두 0건이었다.
- 같은 프롬프트를 이틀에 걸쳐 두 번 돌린 결과가 텍스트만 +1장, 이미지 0장으로 달랐다(아래 편차 기준선).

## 2. OCR 글자 수 구간별 비교 (프롬프트 v1, 맞음/표본, 1차 / 재측정)

공백 제외 OCR 글자 수 기준. 경계는 하한 포함, 상한 미포함.

| 구간 | 표본 | 텍스트만 | 텍스트 + 이미지 |
|---|---|---|---|
| 50자 미만 | 15장 | 2 / 3 (13.3% / 20.0%) | **12 / 12** (80.0%) |
| 50자 이상 150자 미만 | 18장 | 8 / 8 (44.4%) | **14 / 13** (77.8% / 72.2%) |
| 150자 이상 | 10장 | **8 / 8** (80.0%) | 6 / 7 (60.0% / 70.0%) |

- 텍스트만의 오답은 글자가 적은 캡처에 몰린다: 오답 평균 84자(25건) vs 정답 평균 191자(18건), ETC로 예측한 오답은 평균 29자(14건)(1차 측정).
  → 오답의 큰 원인은 모델이 아니라 **OCR 글자량 부족**이다. 재측정에서도 오답 유형 중 →ETC가 13건으로 가장 많았다.
- 글자가 충분하면(150자 이상) 텍스트만이 이미지 포함과 비슷하거나 더 맞았다(8/10 vs 6~7/10). 다만 10장이라 1~2장 차이다.
- 텍스트+이미지의 주된 오답은 INFO↔SHOPPING 혼동이다.

## 3. 하이브리드 (150자 기준)

150자 이상은 텍스트만, 150자 미만은 텍스트 + 이미지를 쓴다고 가정하고 표본별로 합친 값이다.

| 전략 | 1차 (10-15) | 재측정 (10-16) | 비고 |
|---|---|---|---|
| 텍스트만 | 41.9% (18/43) | 44.2% (19/43) | |
| 이미지 항상 | 74.4% (32/43) | 74.4% (32/43) | |
| 하이브리드, 기준 50자 | 65.1% (28/43) | 65.1% (28/43) | |
| 하이브리드, 기준 100자 | — | 74.4% (32/43) | |
| **하이브리드, 기준 150자** | **79.1%** (34/43) | **76.7%** (33/43) | 150자 이상 텍스트 8/10 + 150자 미만 이미지 26/33 → 25/33 |
| 하이브리드, 기준 200자 | — | 74.4% (32/43) | |

- **하이브리드 정확도는 76.7~79.1%로 적는다.** 단일 값이 아니라 같은 프롬프트의 두 번 측정 범위다.
- **하이브리드가 "이미지 항상"보다 낫다는 정확도 이득은 +1~+2장(2.3~4.7%p)이라 실행 간 편차(±1장) 범위에 가깝다.**
  하이브리드를 고르는 주된 근거는 정확도 이득이 아니라 **150자 이상 캡처(약 23%)는 이미지를 보내지 않아 비용·전송량·개인정보 노출이 줄어든다**는 점이다.
- 기준 100자·200자에서는 이미지 항상과 같은 74.4%였다. 기준값 민감도는 50자(65.1%)에서만 크게 떨어진다.
- 이미지를 쓰는 비율은 33/43(77%)이라 장당 비용은 이미지 항상 쓰는 경우보다 약간 낮은 수준(약 $0.0005 근사)이다.
  구간별 실제 토큰을 따로 재지 않은 추정이다.
- 이 값은 **각각 다른 실행의 표본별 결과를 합친 계산**이지 하이브리드 구현을 실제로 돌려 측정한 값이 아니다.

## 프롬프트 v2 실험 (2026-10-16)

v1의 오답에서 INFO↔SHOPPING 혼동과 게시 날짜를 SCHEDULE로 읽은 경우가 보여, 정의는 그대로 두고 **경계 규칙 2개**를 더한 v2를 같은 43장·같은 정답으로 비교했다.
(1) SHOPPING은 구매 의도(가격·구매 버튼·장바구니·주문)가 보일 때만, 정보 전달 위주면 INFO. (2) 게시·작성 날짜는 일정이 아니고, SCHEDULE은 앞으로 갈 날짜·시간과 함께 해야 할 일·장소·예약이 있을 때만.
앱 이름·컬렉션 이름 힌트는 정보량이 낮거나 추출이 안 돼 이번에 제외했다.

### 결과 (엄격 정확도, 맞음/43)

| | v1 1차 (10-15) | v1 재측정 (10-16) | v2 (10-16) | v1→v2 | v1 일간 편차 |
|---|---|---|---|---|---|
| 텍스트만 | 41.9% (18) | 44.2% (19) | 46.5% (20) | +1 | +1 |
| 텍스트 + 이미지 | 74.4% (32) | 74.4% (32) | 69.8% (30) | **−2** | 0 |
| 하이브리드 150자 | 79.1% (34) | 76.7% (33) | 69.8% (30) | **−3** | −1 |

글자 수 구간별 (맞음/표본, 1차 / 재측정 / v2):

| 구간 | 텍스트만 | 텍스트 + 이미지 | 하이브리드 |
|---|---|---|---|
| 50자 미만 (15) | 2 / 3 / 3 | 12 / 12 / **9** | 12 / 12 / **9** |
| 50~149자 (18) | 8 / 8 / 9 | 14 / 13 / 13 | 14 / 13 / 13 |
| 150자 이상 (10) | 8 / 8 / 8 | 6 / 7 / 8 | 8 / 8 / 8 |

카테고리별 SHOPPING (맞음/16): 텍스트만 8 / 8 / 8, 텍스트+이미지 13 / 13 / **8**, 하이브리드 — / 14 / **9**.
INFO(22)는 이미지 15 / 15 / 17, 하이브리드 — / 15 / 16으로 소폭 올랐다. 다른 카테고리는 표본이 1~3장이라 해석하지 않는다.

### 편차 기준선

같은 v1 프롬프트를 이틀에 걸쳐 두 번 돌린 차이가 텍스트 +1장, 이미지 0장, 하이브리드 −1장이었다.
합계가 같아도 카테고리 수준에서는 최소 1~2장이 서로 뒤집혔다(텍스트: PLACE +1, INFO +1, ETC −1 / 이미지: ENTERTAINMENT +1, PLACE −1).
→ **±1장 이내의 차이는 temperature 1.0의 편차로 보고 효과로 해석하지 않는다.** 어제 v1은 표본별 기록이 없어 집계·카테고리 수준으로만 잡은 기준선이다.

### v2의 효과 (오늘 v1 → v2, 표본별 비교)

| | 고쳐짐 | 새로 틀림 | 순변화 | 예측이 달라진 표본 |
|---|---|---|---|---|
| 텍스트만 | 2 | 1 | +1 | 5/43 |
| 텍스트 + 이미지 | 3 | 5 | **−2** | 8/43 |

오답 유형 건수 (v1 → v2):

| 유형 | 텍스트만 | 텍스트 + 이미지 |
|---|---|---|
| →ETC | 13 → 14 | 0 → 0 |
| INFO → SHOPPING | 3 → 3 | 4 → 3 |
| SHOPPING → INFO | 2 → 2 | 3 → **8** |
| →SCHEDULE | 3 → 2 | 2 → 1 |

- **텍스트만 +1장은 편차 범위(±1) 안**이라 효과가 불확실하다. →ETC(13~14건)는 OCR 글자 부족이 원인이라 프롬프트 규칙으로 줄지 않았다.
- **날짜 규칙**(→SCHEDULE)은 방향이 맞고 SCHEDULE로 새로 틀린 표본은 없었지만, 줄어든 것이 후보당 1장이라 효과가 불확실하다.
- **SHOPPING 회귀**: 이미지 후보에서 SHOPPING→INFO 오답이 3 → 8건으로 5건 늘었다. SHOPPING 정답은 13 → 8/16으로 떨어졌고, v1에서는 이틀 모두 13/16으로 안정적이었다.
  하이브리드는 SHOPPING 14 → 9/16으로, 전체 −3장(편차 기준선 −1)의 대부분이 여기서 나왔다.

### 회귀 원인

- 회귀한 5건의 OCR 길이는 0·1·15·70·94자로 모두 짧아, 이미지가 판단하던 표본이다. v1은 이미지에 보이는 상품·가격 단서로 SHOPPING을 맞혔던 것으로 보이고(OCR 텍스트에는 근거가 거의 없다),
  v2의 규칙 1("구매 단서가 있어야 SHOPPING")이 구매 버튼 같은 단서가 없는 상품 소개 캡처를 INFO로 돌린 것으로 판단한다. 모델의 판단 근거를 직접 확인한 것은 아니고 정답·예측·OCR 길이에서 추정한 원인이다.
- **규칙 1이 카테고리 정의("가격·할인·장바구니·배송이 보이면 대개 SHOPPING")와 충돌한다.** 라벨은 정의 기준으로 붙였으므로, 규칙이 사실상 라벨 기준과 다른 기준을 모델에 준 셈이다.
- 텍스트만 후보는 같은 5건 중 4건을 v1에서도 이미 ETC/INFO로 틀리고 있었고 나머지 1건은 v1·v2 모두 맞혀서, 이 규칙의 악영향이 텍스트 결과에는 나타나지 않았다.
- 통계적 한계: 고쳐짐 3 대 새로 틀림 5는 부호 검정으로 유의하지 않다(p≈0.7). 다만 한 유형에 5건이 몰렸고 메커니즘으로 설명되어 규칙 1이 원인이라고 판단한다.

### 결론: v1 유지, v2 채택하지 않음

- **운영 프롬프트는 v1을 쓴다.** v2는 하이브리드(운영 경로) 정확도가 편차 기준선보다 크게 낮았다(−3장 vs −1장).
- v2 코드는 `--experiment.prompt=v2` 실험 옵션으로만 남기고 기본값은 v1이다("채택 안 됨, 사유: SHOPPING 회귀").
- 규칙 2만 담은 v3는 진행하지 않는다. 기대 효과가 1~2장이라 편차 범위 안이고, 43장에서 확인하기 어렵다.
- 프롬프트 규칙 튜닝은 우선순위를 낮춘다. 오답의 큰 덩어리(→ETC)는 규칙이 아니라 입력(OCR 글자량)의 문제다.

## 4. 모델 선택 이유

- **`gemini-3.5-flash-lite`**를 고른 이유는 비용과 무료 한도다.
  - 일반 `gemini-3.8-flash`는 무료 티어가 **하루 20회**라 43장 실험조차 한 번에 못 돌린다(Google AI Studio 비율 제한 화면 확인, 2026-10-15, 무료 등급: flash RPM 5 / RPD 20, flash-lite는 RPM 15 / RPD 500).
  - 1차 실행의 장당 비용은 flash $0.001121 vs flash-lite $0.000241로 **약 4.7배**다.
- **flash의 정확도는 측정하지 못했다.** 1차 실행에서 43장 중 31건이 429로 실패해 12장(33.3%, 4/12)만 평가됐다.
  표본이 너무 적어 flash-lite보다 낫다/못하다고 말할 수 없다. 선택은 정확도 우위가 아니라 **한도와 비용**에 근거한다.
- temperature는 Gemini 3 공식 문서의 권장값 1.0을 쓴다(낮추면 반복·품질 저하 가능).

## 5. 한계

- **표본 43장, 1인 라벨링**: 구간별 표본이 10~18장이라 한두 장이 몇 %p를 움직인다. CHAT·SCHEDULE은 표본이 0장이고 ENTERTAINMENT·ETC는 1장씩이다.
- **기준값 과적합 가능**: 150자는 같은 43장의 구간별 결과를 보고 고른 값이다. 홀드아웃 검증을 하지 않았다. 재측정에서 기준 100자·200자는 이미지 항상과 같은 74.4%, 50자는 65.1%였다.
- **Tesseract는 ML Kit의 근사치**: 실제 앱의 OCR 텍스트 품질·글자 수 분포와 다르다. 글자 수 기준값은 ML Kit 출력으로 다시 맞춰야 한다.
- **temperature 1.0의 실행 간 편차**: 같은 프롬프트 v1을 두 번 돌렸을 때 합계가 텍스트 +1장, 이미지 0장, 하이브리드 −1장 달랐고, 카테고리 수준에서는 그보다 많은 표본이 뒤집혔다. 개선 효과는 이 편차보다 클 때만 주장할 수 있다.
- **비교 구조의 한계**: 어제 v1은 표본별 기록이 없어 오늘 v1과의 표본 단위 비교를 하지 못했고, v2는 v1을 하루 한 번씩만 측정했다(반복 횟수가 적다).
- **비용 비교의 불완전함**: flash 비용은 성공한 12장 기준이고, 하이브리드 비용은 추정이다. 가격은 2026-10-14 공식 문서 기준이며
  `gemini-3.8-flash`는 2027-01-01부터 가격이 오른다.
- **무료 티어 데이터 사용**: 이 실험은 무료 티어로 돌렸고, 무료 티어 입력은 Google 제품 개선에 쓰일 수 있다. 서비스 운영은 유료 등급이어야 한다.

## 6. 다음 단계

1. **ML Kit OCR로 같은 표본을 다시 측정**해 글자 수 분포와 하이브리드 기준값을 재검증한다. 짧은 캡처의 →ETC 오답이 가장 큰 덩어리라 OCR 품질이 정확도를 좌우한다.
2. **표본을 늘린다**(라벨을 분석 전에 확정, 홀드아웃 분리). 기준값을 100/150/200 등으로 바꿔 민감도를 보고, 같은 설정을 반복 측정해 편차 기준선을 표본별로 잡는다.
3. 하이브리드를 실제 구현으로 돌려 측정한다. 사용자 카테고리 수정(앱 기능)으로 쌓이는 정정 데이터를 평가용 라벨로 쓴다.
4. 유료 등급에서 `gemini-3.8-flash`를 같은 표본으로 평가해 정확도 차이가 4.7배 비용을 정당화하는지 본다.
5. 분류 힌트(앱 이름, 인스타 컬렉션 이름)는 ML Kit(텍스트 위치 정보) 도입 후 재검토한다(spec 미정 사항).

## ML Kit 재측정 (2026-10-21)

앱의 실제 OCR(ML Kit 한국어)로 같은 43장·프롬프트 v1·같은 `labels.csv`를 다시 돌렸다. 수치 원본은 `results.mlkit-vs-tesseract.gemini-3.5-flash-lite.md`.

| 입력 | Tesseract | ML Kit | 변화 |
|---|---|---|---|
| 텍스트만 | 44.2% (19/43) | **67.4%** (29/43) | +10장 |
| 하이브리드 150자 | 76.7% (33/43) | 76.7% (33/43) | ±0장 |

- **150자 기준이 바뀐 장은 8장**이다. 전부 Tesseract에서는 150자 미만(이미지 동봉)이었다가 ML Kit에서는 150자 이상(텍스트만)이 됐다. 정답은 두 방식 모두 6장으로 같다.
  → 정확도를 유지하면서 **이미지 전송이 8장 줄었다**(33장 → 25장, 77% → 58%).
- **텍스트만 정확도 차이는 OCR 탓이 맞았다.** 모델·프롬프트·라벨이 같고 OCR만 바꿨는데 +10장이다. Tesseract 실험에서 본 "오답은 글자량 부족" 해석이 확인됐다.
- **ML Kit 하이브리드의 남은 오답 10장**은 OCR이 아니라 카테고리 경계·라벨 문제로 추정한다(파일명·원문 없이 유형만 집계, 정답 → 예측):

| 유형 | 장 | 사용한 입력 |
|---|---|---|
| INFO → SHOPPING | 4 | 이미지 3, 텍스트 1 |
| INFO → SCHEDULE | 2 | 텍스트 |
| SHOPPING → INFO | 2 | 텍스트 1, 이미지 1 |
| INFO → PLACE | 1 | 텍스트 |
| ENTERTAINMENT → SCHEDULE | 1 | 텍스트 |

  INFO↔SHOPPING 혼동이 6장으로 가장 많고, 이는 프롬프트 v2 실험에서 본 경계 문제와 같은 유형이다. 글자가 충분한 텍스트 경로의 오답도 6장 있어 OCR 글자량 문제로는 설명되지 않는다.
- **한계:** 1회 실행·43장이라 ±1장은 temperature 1.0의 실행 편차 범위다. 확장 표본(약 90장)으로 5주차에 재검증한다.
