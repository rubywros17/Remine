# LLM 분류 실험 요약

> 2주차 `LlmClassifier`를 정하기 위한 실험의 결론. 수치의 원본은 `results.*.md`(집계 수치만)이고,
> 파일명·OCR 텍스트·오답 상세는 개인 데이터라 커밋하지 않는다.

## 결론

| 항목 | 결정 |
|---|---|
| 모델 | **`gemini-3.5-flash-lite`**, temperature **1.0** |
| 분류 입력 | **하이브리드** — OCR 150자 이상이면 텍스트만, 150자 미만이면 텍스트 + 축소 이미지 (기준값은 설정) |
| 이미지 전송 | 사용자가 동의한 경우에만, 긴 변 1024px로 축소해 전송, 서버에 저장하지 않음 |

## 조건

- 표본 43장(본인 갤럭시 스크린샷, 1인 라벨링), 실행일 2026-10-15
- OCR은 앱의 ML Kit이 아니라 **Tesseract(kor+eng)** — 근사치
- 모든 후보가 같은 프롬프트(카테고리 7개 고정, JSON 응답), temperature 1.0(Gemini 3 공식 권장값)
- 이미지 변형: 원본을 긴 변 1024px JPEG로 줄여 OCR 텍스트와 함께 전송

## 1. 텍스트만 vs 텍스트 + 이미지

| 입력 | 정확도 | 평균 응답 | 장당 비용 | 1,000장 비용 | 평균 입력 토큰 |
|---|---|---|---|---|---|
| 텍스트만 | **41.9%** (18/43) | 4.8초 | $0.000239 | $0.24 | 456 |
| 텍스트 + 이미지 | **74.4%** (32/43) | 6.1초 | $0.000580 | $0.58 | 1,554 |

- 이미지를 더하면 정확도가 32.5%p 올랐고 비용은 약 2.4배, 응답은 약 1.4초 느려졌다.
- 호출 실패·파싱 실패는 두 후보 모두 0건이었다.

## 2. OCR 글자 수 구간별 비교

공백 제외 OCR 글자 수 기준. 경계는 하한 포함, 상한 미포함.

| 구간 | 표본 | 텍스트만 | 텍스트 + 이미지 | 차이 |
|---|---|---|---|---|
| 50자 미만 | 15장 | 13.3% (2/15) | **80.0%** (12/15) | +66.7%p |
| 50자 이상 150자 미만 | 18장 | 44.4% (8/18) | **77.8%** (14/18) | +33.3%p |
| 150자 이상 | 10장 | **80.0%** (8/10) | 60.0% (6/10) | −20.0%p |

- 텍스트만의 오답은 글자가 적은 캡처에 몰린다: 오답 평균 84자(25건) vs 정답 평균 191자(18건). ETC로 예측한 오답은 평균 29자(14건).
  → 오답의 큰 원인은 모델이 아니라 **OCR 글자량 부족**이다.
- 글자가 충분하면(150자 이상) 텍스트만이 오히려 더 맞았다(8/10 vs 6/10). 다만 10장이라 2장 차이다.
- 텍스트+이미지의 오답은 글자가 많은 캡처에 있다(오답 평균 172자, 11건). 주된 혼동은 INFO↔SHOPPING.

## 3. 하이브리드 (150자 기준)

150자 이상은 텍스트만, 150자 미만은 텍스트 + 이미지를 쓴다고 가정하고 구간별 결과를 합친 값이다.

| 전략 | 정확도 | 비고 |
|---|---|---|
| 텍스트만 | 41.9% (18/43) | |
| 이미지 항상 | 74.4% (32/43) | |
| 하이브리드, 기준 50자 | 65.1% (28/43) | 50자 미만 12/15 + 50자 이상 텍스트 16/28 |
| **하이브리드, 기준 150자** | **79.1%** (34/43) | 150자 이상 텍스트 8/10 + 150자 미만 이미지 26/33 |

- 이미지를 쓰는 비율은 33/43(77%)이라 장당 비용은 이미지 항상 쓰는 경우보다 약간 낮은 수준(약 $0.0005 근사)이다.
  구간별 실제 토큰을 따로 재지 않은 추정이다.
- 이 값은 **각각 다른 실행의 구간별 결과를 합친 계산**이지 하이브리드를 실제로 돌려 측정한 값이 아니다.

## 4. 모델 선택 이유

- **`gemini-3.5-flash-lite`**를 고른 이유는 비용과 무료 한도다.
  - 일반 `gemini-3.8-flash`는 무료 티어가 **하루 20회**라 43장 실험조차 한 번에 못 돌린다(AI Studio에서 확인한 한도).
  - 1차 실행의 장당 비용은 flash $0.001121 vs flash-lite $0.000241로 **약 4.7배**다.
- **flash의 정확도는 측정하지 못했다.** 1차 실행에서 43장 중 31건이 429로 실패해 12장(33.3%, 4/12)만 평가됐다.
  표본이 너무 적어 flash-lite보다 낫다/못하다고 말할 수 없다. 선택은 정확도 우위가 아니라 **한도와 비용**에 근거한다.
- temperature는 Gemini 3 공식 문서의 권장값 1.0을 쓴다(낮추면 반복·품질 저하 가능).

## 5. 한계

- **표본 43장, 1인 라벨링**: 구간별 표본이 10~18장이라 한두 장이 몇 %p를 움직인다. CHAT·SCHEDULE은 표본이 0장이고 ENTERTAINMENT·ETC는 1장씩이다.
- **기준값 과적합 가능**: 150자는 같은 43장의 구간별 결과를 보고 고른 값이다. 홀드아웃 검증을 하지 않았고, 50자 기준이면 65.1%로 크게 달라진다.
  구간 경계 자체도 50/150 두 곳만 비교했다. 다른 표본에서는 최적 기준이 다를 수 있다.
- **Tesseract는 ML Kit의 근사치**: 실제 앱의 OCR 텍스트 품질·글자 수 분포와 다르다. 글자 수 기준값은 ML Kit 출력으로 다시 맞춰야 한다.
- **temperature 1.0의 실행 간 편차**: 같은 텍스트 후보를 두 번 돌렸을 때 전체 18/43은 같았지만 INFO 정답이 8/22와 7/22로 1장 달랐다.
- **비용 비교의 불완전함**: flash 비용은 성공한 12장 기준이고, 하이브리드 비용은 추정이다. 가격은 2026-10-14 공식 문서 기준이며
  `gemini-3.8-flash`는 2027-01-01부터 가격이 오른다.
- **무료 티어 데이터 사용**: 이 실험은 무료 티어로 돌렸고, 무료 티어 입력은 Google 제품 개선에 쓰일 수 있다. 서비스 운영은 유료 등급이어야 한다.

## 6. 다음 단계

1. 실제 앱의 ML Kit OCR로 같은 표본을 다시 측정해 글자 수 분포와 기준값을 재검증한다.
2. 표본을 늘리고(라벨을 분석 전에 확정) 기준값을 100/150/200 등으로 바꿔 민감도를 본다. 하이브리드를 실제 구현으로 돌려 측정한다.
3. 사용자 카테고리 수정(앱 기능)으로 쌓이는 정정 데이터를 평가용 라벨로 쓴다.
4. 유료 등급에서 `gemini-3.8-flash`를 같은 표본으로 평가해 정확도 차이가 4.7배 비용을 정당화하는지 본다.
